# docling-ffi — minimal C ABI for embedders

A single `extern "C"` surface over the docling.rs
[`DocumentConverter`](../docling) (issue #193), for every language with FFI:
C, C++, C#/.NET (`DllImport`), Go (cgo), Java (Panama/JNA), Swift, Zig, …
The deliverables are a shared library (`cdylib`), a static library
(`staticlib`) and the committed [`include/docling.h`](./include/docling.h)
header (generated by [cbindgen](https://github.com/mozilla/cbindgen)).

## API

Five calls — convert, read output, read error, free, version:

```c
#include "docling.h"

DoclingResult *r = docling_convert(bytes, len, "report.docx",
                                   "{\"to\":\"md\",\"strict\":false}");
if (docling_result_error(r)) {
    fprintf(stderr, "%s\n", docling_result_error(r));
} else {
    fwrite(docling_result_output(r), 1, docling_result_output_len(r), stdout);
}
docling_result_free(r);
```

- The result is never `NULL`; exactly one of output/error is set.
- Output is NUL-terminated, so `to` = `md` / `json` reads as a plain C
  string; `to` = `dclx` is a binary zip — always pair
  `docling_result_output()` with `docling_result_output_len()` there.
- `filename` selects the input format by extension (same table as the CLI).
- Every call is reentrant and panic-safe; each result is an independent
  allocation owned by the caller until `docling_result_free`.

## Options

`options_json` is one JSON object (`NULL` or `""` = defaults) whose keys
mirror [docling-serve](../docling-serve)'s request options:

| Key | Values | Meaning |
|---|---|---|
| `to` | `md` (default) \| `json` \| `dclx` | Output format |
| `strict` | bool | Docling-faithful Markdown instead of the readable default |
| `images` | `placeholder` (default) \| `embedded` | Pictures in Markdown: comment placeholder or base64 data URIs |
| `no_ocr`, `force_full_page_ocr`, `no_table_former`, `no_text_panels` | bool | PDF/image pipeline switches |
| `fetch_images` | bool | Resolve external `<img src>` for HTML/EPUB (the embedder owns its network policy) |
| `asr_model`, `asr_lang` | string | Whisper preset / transcription language for audio & video |
| `video_frames` | int | Max sampled video frames (0 = transcript only) |
| `pages` | `"A-B"` or `"N"` | PDF page window (1-based inclusive) |
| `ocr_lang` | `en` (default) \| `ch` | OCR recognition language |

Unknown keys fail the conversion with a clear message — a typo never
silently does nothing.

## Building & linking

```bash
cargo build --release -p docling-ffi
# → target/release/libdocling_ffi.so / .dylib / docling_ffi.dll  (cdylib)
# → target/release/libdocling_ffi.a                              (staticlib)

gcc app.c -I crates/docling-ffi/include \
    -L target/release -ldocling_ffi -o app
```

Declarative formats (Markdown, HTML, DOCX, XLSX, ODF, …) need no assets. The
PDF/image ML pipeline and ASR resolve `.models/` and `.pdfium/` relative to
the process working directory (or the usual `DOCLING_*`/`PDFIUM_*` env
overrides) — fetch them with `scripts/install/download_dependencies.sh`, and
see the [workspace README](../../README.md#getting-the-ml-models). GPU
execution providers are the same pass-through features as everywhere else:
`cargo build -p docling-ffi --features cuda` (then `DOCLING_RS_EP` picks the
provider at startup).

## Regenerating the header

The header is committed; after changing the `extern "C"` surface:

```bash
cbindgen --config crates/docling-ffi/cbindgen.toml \
         --crate docling-ffi \
         --output crates/docling-ffi/include/docling.h
```
